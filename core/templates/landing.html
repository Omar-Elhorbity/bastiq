Multi-tenant SaaS backend · Django + DRF

Every tenant behind its own walls.

Bastiq is a production-ready, multi-tenant SaaS backend — authentication, organizations with role-based teams, and Stripe subscription billing. Its one headline guarantee: each tenant’s data stays sealed behind its own walls, and that boundary is enforced in exactly one place.

Explore the live API → Read the source

Isolation, as an invariant.

The active organization is resolved in exactly one audited place — read from a validated X-Organization-ID header, never from the request body — and a single base view-set scopes every query to it. So no view can forget to scope a query, and a tenant can’t smuggle another org’s id through a payload.

Cross-tenant reads don’t return 403; they return 404. You can’t act on an organization you don’t belong to, and you can’t even learn that another tenant’s rows exist.

Roles that constrain.

Owner, Admin, Member — ranked, with no-privilege-escalation and no-ownerless-organization guards enforced in the API and again at the model layer. A Member can’t change roles or delete the org; an Owner can. Nobody can grant a role above their own, and the last Owner can’t be demoted or removed.

The permission matrix is asserted cell by cell in the test suite — not left to a comment.

Billing you can trust.

The Stripe webhook is the source of truth, not the success redirect: signature-verified on the raw body, idempotent on the event id, and recorded-then-processed in a single transaction, so a mid-flight failure simply reprocesses on Stripe’s retry.

Plan limits are enforced server-side at creation time — Free allows three projects, Pro twenty-five, Business no limit — and a create over the cap returns 402, never a silent overflow.
